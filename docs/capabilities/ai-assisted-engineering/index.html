Engineering principle

Reuse, extend, then create.

AI-assisted changes follow the same abstraction discipline as human-authored engineering. New infrastructure is introduced only when an existing responsibility cannot be reused or extended.

Discover → Reuse → Extend → Create only when required

A request to add a test is not interpreted as permission to invent a new fixture, client, Page Object, helper or architecture. The assistant must first discover which existing responsibility already owns the behavior.

Evidence provenance

Different evidence sources answer different questions.

Repository context, OpenAPI contracts and runtime browser exploration remain separate evidence sources. None is treated as proof of responsibilities owned by another source.

Repository

How should the change belong?

Existing architecture, fixtures, clients, pages, standards and Golden Templates determine framework ownership.

OpenAPI MCP

What does the provider contract expose?

Contract discovery can provide authoritative API paths, operations, payload structure and provider-defined behavior.

Playwright MCP

What does the browser actually expose?

Runtime exploration can provide observable UI structure, browser behavior and interaction evidence.

OpenAPI MCP

Discover contracts instead of inventing them.

OpenAPI MCP can supplement repository context with provider contract evidence when an API implementation requires information that should not be inferred from existing test code.

Repository context + OpenAPI MCP → Provider evidence → AI implementation proposal → Human review

OpenAPI evidence can inform provider behavior, but it does not define the internal framework architecture. Existing repository ownership remains authoritative for implementation structure.

Copilot Agent

Agentic execution remains architecture-governed.

Agent workflows can inspect repository context and execute multi-step engineering tasks, but they remain constrained by the same evidence, architecture, human-review and deterministic validation requirements.

Engineering task → Repository inspection → Golden Template → Agent proposal → Human review → Validation

Agent autonomy does not override framework ownership. Generated changes still require architecture compliance and successful deterministic validation before human approval.

Validation gates

Generated code must pass ordinary engineering standards.

AI involvement does not create a separate definition of correctness. Generated changes pass through the same deterministic validation boundaries as human-authored implementation.

Formatting

Repository consistency

Generated code must satisfy established formatting and code-style requirements.

Type checking

Compile-time integrity

TypeScript validation must succeed without weakening shared types merely to accommodate generated implementation.

Targeted execution

Behavior validation

The affected test layer must execute successfully in its correct runtime and project.

Regression

Shared-impact validation

Broader regression scope is required when generated changes modify shared framework infrastructure.

Responsibility model

AI, evidence and humans have different ownership.

The workflow deliberately separates assistance from authority so that speed does not replace engineering accountability.

Evidence

Describe observable reality

Repository code, OpenAPI contracts and runtime browser evidence establish the context that proposals should respect.

AI

Inspect, propose and implement

Copilot and Agent workflows accelerate analysis and implementation inside the established engineering boundaries.

Human

Own intent and approval

Engineers remain responsible for architecture, evidence sufficiency, semantic correctness and final approval.

AI engineering guardrails

Useful assistance requires explicit limits.

The workflow defines behaviors that AI assistance must not use to create the appearance of successful engineering.

  • Shared domain types
  • Visual baselines
  • Quality thresholds

  • Existing ownership
  • Golden Templates
  • Human review
  • Deterministic validation

  • Generated code as evidence

  • Plausibility as correctness
