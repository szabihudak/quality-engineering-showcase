Quality gate

Validate the codebase before test execution.

Static quality checks act as prerequisites so known source-quality problems do not unnecessarily propagate into downstream execution.

01

Formatting

Code-format validation provides a fast deterministic source quality signal.

02

Type checking

TypeScript validation catches compile-time structural problems before runtime execution.

03

Container build

Only validated source proceeds into the reusable execution image.

Immutable execution identity

Source revision and runtime stay traceable.

Commit-specific image identity creates a direct relationship between source, environment and downstream execution.

Commit SHA ↔ Container image ↔ Execution jobs ↔ Evidence

Downstream jobs reuse the same image rather than independently reconstructing unrelated environments.

Performance workflow

Separate workflow ownership where runtime needs differ.

Performance execution is intentionally separated from the normal functional Playwright pipeline because its tooling and environmental constraints differ.

Failure interpretation

A red job is not a root cause.

Pipeline state is only a signal. Engineering diagnosis determines whether a failure belongs to the product, framework, environment, infrastructure or platform.

CI/CD principles

Reproducibility with explicit trust boundaries.

CI architecture balances environment reuse, execution ownership, diagnostics and security constraints.

01

Build once

Create one runtime image for a validated source revision.

02

Run by responsibility

Separate jobs according to quality ownership.

03

Reuse immutable input

Downstream execution uses the same commit-specific image.

04

Separate evidence

Reports are artifacts; container images are infrastructure.

05

Respect trust boundaries

Privileged operations depend on execution context.

06

Diagnose in context

Job color alone does not explain engineering root cause.
